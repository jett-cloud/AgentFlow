# Workflow Assist node intents

These sections describe what the Agent submits. They are not runtime `node.data` templates.

## start

Use `build_node`. Typed structure is available with `kind: start` and explicit input variables. Variable names
must be unique; runtime form defaults such as text length are generated by the Compiler.

## end

Use `build_node`. Typed structure is available with `kind: end` and explicit output source selectors. Omit the
output `type`: the Compiler derives it from the selected source and rejects unavailable or conflicting types.

## answer

Use `build_node`. Typed structure is available with `kind: answer` and non-empty content. Submit answer content,
not runtime `variables`.

## llm

Use `build_node`. Typed structure is available with `kind: llm`, an exact model returned by `list_models`, and
non-empty prompt messages. Every `{{#node.output#}}` binding in prompt text must resolve in the current graph or
container scope. Do not invent provider/model names.

## knowledge-retrieval

Use `build_node` with `kind: knowledge-retrieval`, one or more exact dataset ids returned by `search_datasets`, and
at least one of `query` or `attachment`. Query must resolve to string; attachment must resolve to file or
array[file]. The Compiler validates the frozen dataset snapshot and generates multiple-retrieval, metadata, rerank,
and vision defaults. Do not submit runtime retrieval config.

## code

Use `build_node`. Typed structure is available with `kind: code`, source code, language, explicit bindings, and
typed declarations in top-level `intent.outputs`. The Compiler generates runtime `variables` and `outputs`.

## template-transform

Use `build_node`. Typed structure is available with `kind: template-transform`, a template, and explicit named
bindings. The Compiler verifies every selector and generates runtime `variables`.

## http-request

Use `build_node` with `kind: http-request`, method, URL, semantic header/parameter pairs, and a typed body. Body
kinds are `none`, `raw-text`, `json`, `form-data`, `x-www-form-urlencoded`, and `binary`; file fields use source
selectors. Plaintext credentials are forbidden in URL, headers, parameters, and authorization. Authentication may
only use `authorization: {"kind":"reference","reference_id":"..."}` from the capability snapshot. The current
runtime has no secure HTTP credential hydrator, so its snapshot is empty and authenticated requests fail closed;
use no-auth until that service capability exists.

## tool

Use the dedicated `build_tool_node` tool with an inspected catalogue binding.

## agent

Use the dedicated `build_agent_node` tool with model, inputs, outputs, tools, and knowledge Intent.

## if-else

Use `build_node` with `kind: if-else`, explicit case ids, and conditions containing only `source`, `operator`, and
the optional comparison `value`. Do not submit `type`, `varType`, condition ids, ELSE cases, or `_targetBranches`.
The Compiler resolves each source type, validates the operator/value pair, generates condition ids, and reserves the
`false` edge handle for ELSE.

## question-classifier

Use `build_node` with `kind: question-classifier`, a string `query` selector, an exact model returned by
`list_models`, and at least two classes with unique ids and names. The Compiler generates runtime model defaults,
vision settings, and `_targetBranches` from the class ids.

## parameter-extractor

Use `build_node` with `kind: parameter-extractor`, a string `query` selector, an exact model, and unique parameter
definitions. Legal parameter types are `string`, `number`, `boolean`, `array[string]`, `array[number]`,
`array[boolean]`, and `array[object]`. Omit top-level `intent.outputs`: outputs are derived from the parameters.

## document-extractor

Use `build_node` with a typed source selector:

```json
{
  "objective": "Extract text from the uploaded document",
  "structure": {
    "kind": "document-extractor",
    "source": ["start", "document"]
  }
}
```

The source must resolve to `file` or `array[file]`. In Advanced Chat, `["sys", "files"]` is valid. Do not submit
runtime-only `variable_selector` or legacy `is_array_file`; the Compiler generates the runtime config.

## variable-aggregator

Use `build_node` with `kind: variable-aggregator` and `sources`. Do not submit `output_type`; the Compiler resolves
all sources and accepts only one strict canonical type. Unknown, `any`, or incompatible branch types are errors.

## list-operator

Use `build_node` with `kind: list-operator`, an array `source`, and optional semantic `filters`, `sort`, `limit`, and
`extract_serial`. Scalar arrays use keyless filters; object-array filters and sorting require field keys. The
Compiler validates operators and ranges and emits the runtime `filter_by` / `order_by` / `limit` / `extract_by`
shape.

## assigner

Use typed Intent on both top-level `build_node` and standard children inside `build_loop`.

```json
{
  "objective": "Store the revised document for the next pass",
  "structure": {
    "kind": "assigner",
    "assignments": [
      {
        "target": ["revision_loop", "optimized_doc"],
        "operation": "over-write",
        "value": {
          "kind": "variable",
          "selector": ["optimize_llm", "text"]
        }
      }
    ]
  }
}
```

`target` is an exact declared writable variable selector: a Loop variable inside a container, or a Conversation
variable advertised as writable by `inspect_node_schema` at top level. Never put a natural-language description in
`target`. Supported operations are `over-write` and `clear`.

## human-input

Use `build_node` with `kind: human-input`, form content, typed form inputs, one or more delivery intents, and unique
actions. Choose only delivery methods returned by `inspect_node_schema`. Email accepts only real
`member_reference_ids` from that same run and its body must contain `{{#url#}}`; never invent an email or member id.
Action ids must be identifiers of at most 20 characters. New nodes default to a three-day timeout; updates preserve
the old timeout when omitted. Do not submit delivery UUIDs or `_targetBranches`; the Compiler and graph
postprocessor generate them.

## iteration

Use the dedicated `build_iteration` tool. Child nodes use request-local `ref` values.

## loop

Use the dedicated `build_loop` tool. Declare Loop variables before children reference or assign them.
